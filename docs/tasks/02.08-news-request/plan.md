# Приём новостей от игроков — тикет-система

Ветка `feat/news-request`, отрезана от `origin/master` (f038bc6). Tier-1.

## Задача

В канале новостей (`channels.news_request`) — панель с ОДНОЙ кнопкой «Отправить
новость». Клик → модалка (ник, текст новости, доп. инфо) → приватный тред с автором
и ролью репортёров → в треде компонент бота с кнопками «✅ Новость опубликована» /
«⛔ Отклонить». Кнопки жмут ТОЛЬКО репортёры. Каждое нажатие уезжает в три места:

1. `channels.ticket_log` — архив с транскриптом треда и AI-выжимкой (как у багов);
2. `channels.reporters_chat` — короткая карточка «что решили»;
3. ЛС автору новости.

Тред после решения удаляется (транскрипт уже в логе).

## Подход

Вариант A: отдельный ког `bot/handlers/tickets/news_request.py` по образцу
`bugs.py`. `TicketEngine` не трогаем в логике — только выносим из него
`_archiveTicket` в модульную функцию, чтобы архив с транскриптом переиспользовать.

Отклонено: расширение `TicketEngine` третьей веткой (`is_support` → тройное
ветвление на живом контуре багов и админ-тикетов); обобщение движка под конфиг
типов тикетов (переусложнение ради одной сущности).

## Проверка простоты (ponytail lite)

- не делаем: свою команду-постер панели — панель публикуется существующим
  `/send_embed`, достаточно добавить контейнер в `storage.Embeds`;
- не делаем: свой сборщик транскрипта и AI-выжимки — переиспользуем
  `_archiveTicket` из `engine.py`, вынеся его в функцию;
- не делаем: обобщение рейт-лимита с багами — у `bug_rate_limit_ok` нет тестов,
  рефактор ради второго потребителя рискованнее локальной копии на 18 строк;
- не делаем: отдельную запись в `data/` про заявки — состояние держат флаги
  (`created_by` на треде), как у багов.
