# 28.07 · «Опять ни одна кнопка не работает»

## Симптом

Серёжа: кнопки по всему серверу не срабатывают. В `bot.log` два кода отказа
вперемешку: `10062 Unknown interaction` и `40060 Interaction has already been
acknowledged`, в пяти разных хендлерах (news_editor, tickets/engine,
tickets/bugs, vk_repost, catcraft_fm). За 28.07 — 11 записей.

## Что проверено и ОТБРОШЕНО (первоисточники, не прошлый вывод)

- **Второй инстанс на VDS** — нет: `ps` показывает один `main.py` (pid 214099,
  аптайм 1д18ч), в `systemd` один юнит, в docker только VPN, процессов с
  `DISCORD_TOKEN` в окружении больше нет.
- **Затык event loop** — нет: вотчдог лага из #34 (порог 1.5с) с 27.07 00:57
  не написал ни строки; loadavg 0.7; CPU бота 18%.
- **Сеть до Discord** — нет: ping 2 мс, TLS-хендшейк 70–110 мс, потерь 0.
- **Протухший keep-alive** (aiohttp переиспользует мёртвый сокет) — нет:
  проба на проде, паузы 20/45/70/120с, все повторные запросы 80–115 мс, 200.
- **Часы VDS** — нет: chrony, расхождение 0.08 мс.
- **Дубль кога / два хендлера на один custom_id** — нет: по одному листенеру
  на каждый `custom_id`, коги регистрируются по одному разу.

## Диагноз

Второй процесс, залогиненный **боевым токеном**, вне VDS (ноутбук, чужая
песочница). Ровно тот рецидив, что уже был 25–27.07 и лечился сбросом токена:
`python main.py` без `BOT_ENV=dev` берёт из `.env` боевой `DISCORD_TOKEN` и
поднимает ВТОРОЙ прод. Оба процесса получают все интеракции, кто первый
подтвердил — тот и ответил, второму Discord отвечает 40060, а если тот
тормознул — 10062. (Правило живёт в `.claude/rules/local-run.md`, но `.claude/`
в `.gitignore` — поэтому суть продублирована здесь.)

**Как отличить от гонки внутри одного процесса.** Тот же 40060 даёт пара
листенеров на один `custom_id` в нашем же коде. Проверка: `git grep` по
`custom_id` — на 28.07 пересечений нет, на каждый id ровно один листенер;
значит подтверждает кто-то снаружи. Если пересечение появится — сначала
чинить его, а не сбрасывать токен.

Опоры:

1. `GET /gateway/bot` → `session_start_limit`: за текущее суточное окно
   израсходовано 3 IDENTIFY, при том что наш прод не перезапускался с 27.07
   00:57 (`ActiveEnterTimestamp` неизменен) и не переподключался (`Бот готов`
   в логе последний раз тогда же). Замеры 998 → 997 → 997 с интервалами
   4 и 3.5 минуты — логинится кто-то ещё.
2. 18:30:08 наш процесс ставит флаг `created_bugs`, 18:30:09 получает 40060 на
   `send_modal` — а в 18:30:23 в логе появляется `created_by` на новом треде:
   **модалка у пользователя открылась**. Значит её открыл не наш процесс.
3. 40060 в хендлере, где до ответа нет ни одного `await` (`ticketButtons`,
   engine.py:417), невозможен от собственной медлительности — только от
   чужого подтверждения.

Уверенность: высокая, но не 100% — прямого доказательства (сессия чужого
процесса) API не отдаёт. Проверяется однозначно: сброс токена убивает все
сессии разом; если отказы прекратились — диагноз верен.

## Лечение — за Серёжей (я не могу)

1. Discord Dev Portal → Reset Token.
2. Новый токен в `.env` на VDS, `systemctl restart robocat`.
3. Найти и погасить рогуль-процесс (`BOT_ENV=dev` обязателен при локальном
   запуске — иначе поднимается второй ПРОД).

## Что сделано в этой ветке

- `handlers.get_a_job` добавлен в `extensions` — ког не был зарегистрирован
  НИКОГДА (`git log -S` по main.py пуст), кнопка «Посмотреть доступные
  вакансии» молчала с рождения. Это отдельная, настоящая «кнопка не работает».
- `on_error` дописывает возраст интеракции и прямым текстом называет второй
  инстанс на кодах 40060 / быстрый 10062 — чтобы следующий рецидив читался с
  первой строки лога, а не расследовался ночь.
- Тест `test_cog_module_registered_in_main`: любой модуль с `def setup(bot)`,
  которого нет в `extensions`, теперь красит CI. Класс бага «ког написан, но
  мёртв» закрыт целиком, а не в одном экземпляре.
